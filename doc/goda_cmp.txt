==============================================================================
INTRODUCTION                                           *goda-cmp-introduction*

goda-cmp.vim is a completion plugin built on goda.vim (|goda.txt|).  It is a
successor in spirit to ddc.vim: sources and filters are separate extensions,
the popup is either Vim's native one or pum.vim, and the configuration is
code, a small Go program you own.

There is no plugin loader and no manifest: an extension is a Go package that
your `main.go` imports, so versions are pinned by your `go.mod` and your
editor type-checks and completes the configuration.

==============================================================================
INSTALL                                                     *goda-cmp-install*

Requirements: Go 1.26 or later; Vim 9.1 or later (|+job| |+channel|
|+timers|) or Neovim; goda.vim; pum.vim if you want the pum popup.

1. Install goda.vim and goda-cmp.vim with your plugin manager.

2. Create your configuration, a Go module of your own: `main.go`, `config.go`,
   `go.mod`, `go.sum`.  Keep it with the rest of your editor configuration.
   The default place is `~/.vim/goda-cmp` for Vim and
   `stdpath('config')/goda-cmp` for Neovim; see |g:goda_cmp#config_dir|. >

	mkdir -p ~/.vim/goda-cmp && cd ~/.vim/goda-cmp
	cp /path/to/goda-cmp.vim/examples/config/{main.go,config.go} .
	go mod init goda-cmp-config
	go get github.com/Shougo/goda-cmp.vim@latest
	go mod tidy
<
3. Add to your vimrc: >vim

	autocmd VimEnter * call goda_cmp#enable()
	inoremap <expr> <C-n> pumvisible() ? "\<C-n>"
	      \ : "\<Cmd>call goda_cmp#complete()\<CR>"
<
4. Build and start: >vim

	call goda_cmp#build()
	call goda_cmp#enable()
<
The binary is not put in the configuration directory: it depends on your
machine, so it goes to a cache directory (see |g:goda_cmp#binary|).

The binary has to be built again after you edit `main.go` or `config.go`, or
update goda.vim, goda-cmp.vim or an extension: >

	go get -u github.com/Shougo/goda-cmp.vim github.com/Shougo/goda.vim
	go mod tidy
<
and |goda_cmp#build()|.  To build whenever you save the configuration: >vim

	autocmd BufWritePost ~/.vim/goda-cmp/*.go call goda_cmp#build()
<

FUNCTIONS                                                 *goda-cmp-functions*

                                                            *goda_cmp#build()*
goda_cmp#build()
		Run `go build` in |g:goda_cmp#config_dir|.  When completion is
		running it is stopped first and started again with the new
		binary.  When the build fails the error is thrown and the
		previous binary keeps running.

                                                           *goda_cmp#enable()*
goda_cmp#enable()
		Start the binary and begin completing in insert mode.  When
		the binary does not exist yet a hint is shown instead.  When
		it was built from a configuration with errors (an unknown
		filter, say), it throws with those errors and stops the
		binary.

                                                          *goda_cmp#disable()*
goda_cmp#disable()
		Stop completing and stop the binary.

                                                         *goda_cmp#complete()*
goda_cmp#complete([{options}])
		Complete now (ddc.vim's "Manual" event): every source is
		asked, and the automatic lengths do not apply (the manual
		ones do).  {options} is a patch for this request only, as
		|goda_cmp#patch_global()| takes.  While the list is open,
		typing on narrows it as a manual completion with the same
		sources and UI, as in ddc.vim.

                                                             *goda_cmp#hide()*
goda_cmp#hide([{event}])
		Close the popup.  {event} is for compatibility with
		ddc#hide().

                                                          *goda_cmp#visible()*
goda_cmp#visible()
		Whether the popup is open: the UI is asked when it can tell
		(cmp.Visibler).

                                               *goda_cmp#skip_next_complete()*
goda_cmp#skip_next_complete()
		Skip the next automatic completion.

                                                         *goda_cmp#on_event()*
goda_cmp#on_event({event})
		Act as if the autocmd {event} happened: the sources that
		listen to it hear about it, and it completes when it is in
		autoCompleteEvents.

                                                 *goda_cmp#on_complete_done()*
goda_cmp#on_complete_done({item})
		For a UI that is not goda-cmp's: the user accepted {item}, a
		complete-item that came from goda-cmp.

                                                     *goda_cmp#update_items()*
goda_cmp#update_items({name}, {items})
		Replace the items the source {name} gathered for the word
		being typed with {items} (complete-items) and show the list
		again, as ddc#update_items().  Nothing happens when the
		source has not gathered for this word.

                                                      *goda_cmp#get_current()*
goda_cmp#get_current()
		The configuration in effect for the current buffer: the Go
		and Vim script settings together.

                                                            *goda_cmp#alias()*
goda_cmp#alias({type}, {alias}, {base})
		Name the extension {base} of {type} ("source", "filter" or
		"ui") also {alias}, as ddc#custom#alias().  The alias can
		have options and params of its own: >vim

	call goda_cmp#alias('source', 'around_long', 'around')
	call goda_cmp#patch_global(#{
	      \   sources: ['around', 'around_long'],
	      \   sourceParams: #{ around_long: #{ minLength: 10 } },
	      \   sourceOptions: #{ around_long: #{ mark: 'A+' } },
	      \ })
<
                                                 *goda_cmp#enable_terminal()*
goda_cmp#enable_terminal()
		Complete in terminal buffers too; see |goda-cmp-terminal|.
		Enables goda-cmp first if needed.

                                                *goda_cmp#disable_terminal()*
goda_cmp#disable_terminal()
		Stop completing in terminal buffers.

                                                    *goda_cmp#get_previewer()*
goda_cmp#get_previewer({item})
		Return what the source of {item} shows for it in a preview
		window, in the format of ddc.vim's previewers: a dictionary
		with "kind" ("empty", "help", "text", "markdown" or
		"command") and "tag", "contents" or "command".  "empty" for
		an item that is not goda-cmp's, or whose source has nothing
		to show.  See |goda-cmp-preview|.

                                                   *goda_cmp#enable_cmdline()*
goda_cmp#enable_cmdline()
		Complete on the next command line, until it is left; see
		|goda-cmp-cmdline|.  Enables goda-cmp first if needed.

                                                  *goda_cmp#disable_cmdline()*
goda_cmp#disable_cmdline()
		Stop completing on the command line now.

                                                     *goda_cmp#patch_global()*
goda_cmp#patch_global({patch})
goda_cmp#patch_filetype({filetype}, {patch})
goda_cmp#patch_buffer({patch})
		Merge {patch} into the settings; see |goda-cmp-patch|.
		{filetype} may be a list of filetypes.

                                                       *goda_cmp#get_global()*
goda_cmp#get_global()
goda_cmp#get_filetype({filetype})
goda_cmp#get_buffer()
		Return a copy of the patches made from Vim script.

                                                       *goda_cmp#set_global()*
goda_cmp#set_global({config})
goda_cmp#set_filetype({filetype}, {config})
goda_cmp#set_buffer({config})
		Replace the patches made from Vim script.

CONFIGURATION                                                *goda-cmp-config*

The configuration is Go code; see `examples/config`.  Its shape mirrors
`ddc.ts`: >go

	b := cmp.New()
	b.AddUI(native.New())
	b.AddSource(around.New(around.Params{MinLength: 2}))
	b.AddFilter(matcherhead.New(matcherhead.Params{}))
	b.PatchGlobal(cmp.Config{
	    UI:      "native",
	    Sources: []string{"around"},
	    SourceOptions: map[string]cmp.SourceOption{
	        "_":      {Matchers: []string{"matcherhead"}},
	        "around": {Mark: "A"},
	    },
	})
	b.PatchFiletype("markdown", cmp.Config{})
	b.Main()
<
Patches merge field by field: unset fields keep the previous value, maps are
merged by key, slices are replaced.  Options named "_" are inherited by every
source.  A name used but never added is reported when the binary starts.
Nothing is built in: even the popup is an extension, and `UI` must name one
that was added (there is no default).

Settings are those of ddc.vim, with the same names in Vim script
(`sourceOptions`, `autoCompleteEvents`, ...).  Where goda-cmp differs, it says
so below.
	UI			a UI added with AddUI ("native", "pum")
	Sources			enabled sources, in order
	SourceOptions		per source, "_" for all; see
				|goda-cmp-source-options|
	CmdlineSources		sources of the command line, by
				|getcmdtype()|; see |goda-cmp-cmdline|
	PostFilters		filters run on the merged list
	SourceParams		parameters of sources, by name, set from Vim
	FilterParams		script; see |goda-cmp-params|
	UIParams
	AutoComplete		completion while typing (default on; goda-cmp
				only)
	AutoCompleteDelay	debounce in ms (default 0)
	AutoCompleteEvents	the autocmd events that complete (default
				InsertEnter, TextChangedI, TextChangedP,
				CmdlineEnter, CmdlineChanged, TextChangedT;
				ddc.vim's default has the first three, but the
				others happen only after
				|goda_cmp#enable_cmdline()| and
				|goda_cmp#enable_terminal()|)
	BackspaceCompletion	complete after a backspace too (default off:
				the popup is closed instead)
	HideOnEvents		close the popup before completing (default
				off)
	SpecialBufferCompletion	complete where 'buftype' is not empty
				(default off; the command line always is)
	ContextFiletype		where the filetype of a request comes from:
				"none" (default, 'filetype'),
				"context_filetype" (context_filetype.vim) or
				"treesitter" (Neovim's parser at the cursor).
				It decides which filetype settings apply, so
				it can be set globally or for a buffer only.
				It is ddc#enable()'s context_filetype.
	PartialInterval		least ms between popup updates while a
				|goda-cmp-partial| source answers (default 50)
	SourceTimeout		bound for every source and filter in ms
				(default 2000)

Where zero is a real value the field is a pointer, so that "not set" (nil)
differs from 0 or false: write `new(0)` (Go 1.26).  A configuration written
for an earlier version replaces `cmp.Ptr(` with `new(`.
KeywordPattern is a regular expression in Go's RE2 syntax (no lookaround) for
the text before the cursor; the match must end at the cursor.
ForceCompletionPattern is one too, matched the same way: when it matches,
MinAutoCompleteLength is ignored for that source, as in ddc.vim.  `\.\w*`
completes members right after the dot.

`DynamicConfig`, `DynamicSources`, `DynamicUI` and the source option
`DynamicFilters` are functions and can only be set in Go.  `DynamicConfig`
returns a patch for one request, laid over everything else; it takes the place
of ddc#custom#set_context_*(): >go

	DynamicConfig: func(ctx context.Context, h sdk.Host,
	    a cmp.DynamicConfigArgs) (cmp.Config, error) {
	    in, err := h.Call(ctx, "goda_cmp#syntax#in", "Comment")
	    if err != nil || in != true {
	        return cmp.Config{}, err
	    }
	    return cmp.Config{Sources: []string{"around"}}, nil
	},
<
                                                     *goda-cmp-source-options*
Source options (`SourceOptions`, ddc.vim's ddc-source-options):
	Mark			shown in the menu column
	MinAutoCompleteLength	shorter words do not complete automatically
				(default 1; ddc.vim: 2)
	MaxAutoCompleteLength	nor longer ones (default 80)
	MinManualCompleteLength	the same for |goda_cmp#complete()|
	MaxManualCompleteLength	(default 0 and 80)
	MinKeywordLength	items with shorter words are dropped
	MaxKeywordLength	and with longer ones (default 0: no limit)
	MaxItems		items kept after sorting (default 100)
	KeywordPattern		the text completed, before the cursor
	ForceCompletionPattern	when it matches, the lengths do not apply
	IgnoreCase		for the matchers (`FilterInput.IgnoreCase`)
	MatcherKey		the item attribute the matchers compare:
				"abbr", "menu", "kind" or "info"
	Dup			an item whose word is there already: "ignore"
				(default) drops it, "keep" keeps both,
				"force" drops the earlier one
	EnabledIf		a Vim expression; the source is used only when
				it is true
	Timeout			bound for the source in ms (default
				SourceTimeout)
	HideTimeout		when the source has not answered after this
				many ms, the popup is hidden (default 200); a
				plain source is then left out of the request
				(as in ddc.vim), a StreamSource goes on
	IsVolatile		ask the source on every keystroke instead of
	VolatilePattern		filtering what it gathered again; with the
				pattern, only when it matches
	CacheTimeout		keep what the source gathered this many
				seconds, even when the word goes out of the
				lengths (default 0)
	ReplaceSourceInputPattern
				the first match is removed from the text the
				source sees
	Preview			false turns the source's previewer off
	Matchers, Sorters, Converters
				the filters, in order: matchers, sorters,
				MaxItems, converters

What a source gathered is kept and filtered again while the word is typed on
(the same line and start), as in ddc.vim: the source is not asked again.
So a source with a fixed list needs matchers.  A source whose answer depends
on everything typed says so with `Gathered.Incomplete` (ext/source/lsp and
ext/source/cmdline do), or is made volatile with IsVolatile.
|goda_cmp#complete()| always asks.

==============================================================================
RUN-TIME PATCHES                                              *goda-cmp-patch*

Extensions are fixed when you build; settings are not.  Vim script can patch
them at any time: >vim

	call goda_cmp#patch_global({'ui': 'pum'})
	call goda_cmp#patch_filetype('go', {'sources': ['around']})
	let prev = goda_cmp#get_buffer()
	call goda_cmp#patch_buffer({'sourceOptions':
	      \ {'_': {'keywordPattern': '[0-9a-zA-Z_:#*/.-]*'}}})
	call goda_cmp#set_buffer(prev)
<
A patch is a dictionary with the keys of `cmp.Config`.  Settings apply in this
order, the later one winning: global (Go, then Vim script), filetype (Go,
then Vim script), buffer.  They are kept in Vim script: they survive a
restart of the binary and go away with the buffer.  An invalid patch (unknown
key, wrong type, unknown name) is refused with an error.

                                                             *goda-cmp-params*
`sourceParams`, `filterParams` and `uiParams` set the parameters of
extensions by name, over those given to the constructor in Go: >vim

	call goda_cmp#patch_global(#{
	      \   sourceParams: #{ around: #{ minLength: 3 } },
	      \   uiParams: #{ pum: #{ insert: v:true } },
	      \ })
<
The keys are the JSON names of the extension's Params.  The extension must
implement `cmp.Configurable` (all those of this repository do but
ext/source/lsp, whose settings are Go values); an unknown key is an error.
The parameters of a name are merged by key across the settings.

SELECTING CANDIDATES                                         *goda-cmp-select*

Nothing is inserted until you select a candidate.

With the native popup the usual keys work:
	<C-n> <C-p>	select the next / previous candidate (and insert it)
	<C-y>		accept the selected candidate
	<C-e>		cancel, restoring what you typed

With pum.vim map the keys to its functions: >vim

	inoremap <C-n> <Cmd>call pum#map#insert_relative(+1)<CR>
	inoremap <C-p> <Cmd>call pum#map#insert_relative(-1)<CR>
	inoremap <C-y> <Cmd>call pum#map#confirm()<CR>
	inoremap <C-e> <Cmd>call pum#map#cancel()<CR>
<
You need not set 'completeopt': with the native popup goda-cmp makes sure
that nothing is inserted until you select, and restores your value when you
leave insert mode.

POPUP                                                         *goda-cmp-popup*

A UI is an extension, added like the others and chosen with `UI`: >go

	import "github.com/Shougo/goda-cmp.vim/ext/ui/native"
	import "github.com/Shougo/goda-cmp.vim/ext/ui/pum"

	b.AddUI(native.New())   // "native": Vim's popup menu
	b.AddUI(pum.New())      // "pum": pum.vim, which must be installed
<
pum.vim is configured in Vim script as usual (`pum#set_option()`,
`pum#map#...`).  The UI can differ per filetype, and can be switched from Vim
script among the UIs that were added: `goda_cmp#patch_global({'ui': 'pum'})`.

Both take the parameter `insert` (as ddc-ui-native and ddc-ui-pum): the first
item is inserted when the popup opens, which suits manual completion.  In Go,
`pum.New(pum.Params{Insert: true})`; from Vim script, `uiParams`
(|goda-cmp-params|).

`Resolve` (|goda-cmp-extension|) shows its result through
`pum#update_current_item()` with pum.vim, and in the native popup only when
'completeopt' has "popup" and the item already had an info.

EXTENSIONS                                                *goda-cmp-extension*

An extension is a Go module implementing an interface of package `cmp` and
exporting a constructor.  `Source` has `Name` and `Gather`; `Filter` has
`Name` and `Filter`; `UI` has `Name`, `Show` and `Hide`.  A source that fails, panics or times out is skipped for
that request; the others still answer.

A source for a language server can implement more.  The engine looks for each
interface with a type assertion, so extensions written without them keep
working:
	StreamSource	GatherStream: hand over candidates as they arrive
	Initializer	Init: start something once, in the first request
	CompleteDoner	OnCompleteDone: act when a candidate is accepted
	Resolver	Resolve: fill in an item when it is selected
	Closer		Close: release resources when the plugin stops
	EventHandler	Events, OnEvent: act on buffer events
	Previewer	Preview: what to show in a preview window
			(|goda-cmp-preview|)
	Configurable	WithParams: take parameters from Vim script
			(|goda-cmp-params|); `cmp.PatchParams` does the
			work for a Params struct with JSON tags

`Item` also has FilterText and SortText (LSP filterText and sortText), Dup,
and UserData, which stays in the plugin process and comes back in
OnCompleteDone and Resolve.

A filter gets the Host in `FilterInput.Host`, for the rare one that asks the
editor (the sorter of the command-line history); it is nil when a test calls
the filter directly.

Sources keep their own caches: the engine asks a source on every request, so
a source that got a complete answer can filter it itself for the next
keystrokes.

`Close` is called through goda.vim's `sdk.Closer`; it needs a goda.vim that
has it.

UIs~
A UI may implement more, too:
	Skipper		SkipCompletion: tell a change the UI made itself
			(inserting the selected item) from typing; the
			request is dropped
	InfoUpdater	UpdateInfo: show what Resolve added to the item
	ModesUI		Modes: the modes it can show candidates in, "i"
			(insert mode), "c" (the command line) and "t" (a
			terminal); without it, insert mode only
	Visibler	Visible: whether the popup is open
			(|goda_cmp#visible()|)

The core never calls an extension's Vim script, and has no Vim script of its
own for any UI: an extension calls the editor itself, through the Host it is
given.  A UI with Vim script of its own (`autoload/goda_cmp/ui/{name}.vim`
for the ones of this repository) reports back through these receivers:
	goda_cmp#_fresh({r})		is the list {r} (with "seq" and "tick"
					from the ShowRequest) still wanted?
	goda_cmp#_select({item})	the user moved to {item}
	goda_cmp#_done({item}, {reason})	the user accepted {item}
					({reason} "cancel": dismissed)
{item} is the complete-item the UI was given; its user_data is the
reference that leads back to the source.  The engine itself tells the core's
script what it shows (goda_cmp#_items()), for |goda-cmp-map-functions|.

Buffer events~
An EventHandler names the autocmd events it wants and for which filetypes
(`Events() []EventSpec`); the list is asked once, when the plugin starts, and
the Vim side listens to exactly those, filtering by filetype before anything
is sent.  `OnEvent` gets an `Event` (name, buffer number, changedtick,
filetype, 'buftype' and the full path of the file).  The events of a source
arrive one at a time, in the order Vim saw them.  When goda-cmp is enabled,
the current buffer gets a BufEnter, since its own came before the plugin
started.  There is no setting for this: the source decides, typically from
the filetypes it was configured with.

Package `cmp/cmptest` is a fake editor for testing extensions without Vim.
`cmptest.Host` answers calls with Go functions (`Funcs`) and evaluates simple
expressions made of those calls, lists, strings and numbers.
`cmptest.NewEditor()` adds buffers, a cursor and the buffer functions
(getbufline(), setbufline(), appendbufline(), deletebufline(), ...), which
behave like Vim's, for sources that read or change buffers.

Extensions of this project are named `goda-cmp-source-{name}` and
`goda-cmp-filter-{name}`, with the package `{name}`, registered under the
same name (`matcherhead.New()` is the filter "matcherhead"), and the
constructor `New(Params)` (or `New()` when there is nothing to set).  The
name says nothing about the kind: a filter is a matcher, a sorter or a
converter by the list it is put in.

COMMAND LINE                                                *goda-cmp-cmdline*

Completion on the command line works as in ddc.vim.  It is enabled for one
command line at a time, typically from the mapping that opens it, and its end
fires the |User| autocmd "GodaCmpCmdlineLeave": >go

	import "github.com/Shougo/goda-cmp.vim/ext/source/cmdline"
	import "github.com/Shougo/goda-cmp.vim/ext/ui/pum"

	b.AddUI(pum.New())
	b.AddSource(cmdline.New())
	b.PatchGlobal(cmp.Config{
	    UI: "pum",
	    CmdlineSources: map[string][]string{
	        ":": {"cmdline", "around"},
	    },
	    SourceOptions: map[string]cmp.SourceOption{
	        "cmdline": {Mark: "cmdline"},
	    },
	})
<
>vim
	nnoremap : <Cmd>call CommandlinePre()<CR>:

	function CommandlinePre() abort
	  cnoremap <Tab>   <Cmd>call pum#map#insert_relative(+1)<CR>
	  cnoremap <S-Tab> <Cmd>call pum#map#insert_relative(-1)<CR>
	  cnoremap <C-y>   <Cmd>call pum#map#confirm()<CR>
	  cnoremap <C-e>   <Cmd>call pum#map#cancel()<CR>
	  autocmd User GodaCmpCmdlineLeave ++once call CommandlinePost()
	  call goda_cmp#enable_cmdline()
	endfunction
	function CommandlinePost() abort
	  silent! cunmap <Tab>
	  silent! cunmap <S-Tab>
	  silent! cunmap <C-y>
	  silent! cunmap <C-e>
	endfunction
<
`CmdlineSources` takes the place of `Sources` on the command line; its keys
are the command-line types of |getcmdtype()| (":", "/", "?", "@" for
|input()|, ...).  A type without sources is not completed; "=" (the
expression register) never is.  Sources see `Context.Mode` "c",
`Context.CmdType` and the command line before the cursor as `Input`.

The UI must be able to show candidates there (`cmp.ModesUI` with "c"): "pum" can,
"native" cannot, since |complete()| works in insert mode only.  With
`CmdlineSources` set and a UI that cannot, the binary reports a
configuration error.  The UI can be chosen per filetype, as usual.

`ext/source/cmdline` (a port of ddc-source-cmdline) offers what
|getcompletion()| does for the command line.  Put "fuzzy" in 'wildoptions'
for fuzzy matched items.  It previews the help of an item that has one
(|goda-cmp-preview|).

`ext/source/cmdlinehistory` (a port of ddc-source-cmdline_history) offers
the entries of the history of the command-line type (|histget()|), the newest
first: whole entries while the command line has no space, and after one, the
rest of the entries that start with the same text.  When the command line
completes files or directories, only entries that exist are offered.
`ext/filter/sortercmdlinehistory` (ddc-filter-sorter_cmdline_history) puts
first the candidates found in a recent entry: >go

	import "github.com/Shougo/goda-cmp.vim/ext/filter/sortercmdlinehistory"
	import "github.com/Shougo/goda-cmp.vim/ext/source/cmdlinehistory"

	b.AddSource(cmdlinehistory.New(cmdlinehistory.Params{}))
	b.AddFilter(sortercmdlinehistory.New(sortercmdlinehistory.Params{}))
	b.PatchGlobal(cmp.Config{
	    CmdlineSources: map[string][]string{
	        ":": {"cmdline", "cmdlinehistory"},
	        "/": {"cmdlinehistory", "around"},
	    },
	    SourceOptions: map[string]cmp.SourceOption{
	        "cmdline": {
	            Mark:    "cmdline",
	            Sorters: []string{"sortercmdlinehistory"},
	        },
	        "cmdlinehistory": {Mark: "history"},
	    },
	})
<
Both take `Limit`, the number of entries looked at (1000 for the source, 500
for the sorter, as in ddc.vim).  Outside the command line, the source offers
nothing and the sorter keeps the order.

==============================================================================
TERMINAL                                                   *goda-cmp-terminal*

Completion in |terminal| buffers works as in ddc.vim: enable it, use a UI that
can show candidates there (`cmp.ModesUI` with "t": "pum"), and allow completion in
special buffers: >vim

	call goda_cmp#enable_terminal()
	call goda_cmp#patch_global(#{
	      \   ui: 'pum',
	      \   specialBufferCompletion: v:true,
	      \ })
	tnoremap <C-n> <Cmd>call pum#map#select_relative(+1)<CR>
	tnoremap <C-p> <Cmd>call pum#map#select_relative(-1)<CR>
	tnoremap <C-y> <Cmd>call pum#map#confirm()<CR>
<
TextChangedT completes (it is in the default autoCompleteEvents).  Sources see
`Context.Mode` "t"; Input is the terminal line before its cursor.  pum.vim
cannot insert while selecting in a terminal (pum#map#insert_relative() does
nothing there): select, then confirm, which sends the item to the job,
replacing the typed part with <C-h>s (the shell's erase character must be
<C-h>, `stty erase ^H`).  It needs the TextChangedT event (Vim 9.0.1513 or
Neovim 0.9).

==============================================================================
PREVIEW                                                     *goda-cmp-preview*

A source that implements `Previewer` says what to show for an item in a
preview window, in the format of ddc.vim's previewers (`cmp.Preview`): the
help of a tag, lines of text or markdown, or a command run in the window.
The cmdline source shows the help of an item.  The engine has no window of
its own: a UI that has one asks |goda_cmp#get_previewer()|.  pum.vim does,
with its preview option and its `previewer` option (a pum.vim that has it): >vim

	call pum#set_option(#{
	      \   preview: v:true,
	      \   previewer: 'goda_cmp#get_previewer',
	      \ })
<
An item whose source has no previewer, or gives "empty", shows its info
there instead.

==============================================================================
PARTIAL RESULTS                                             *goda-cmp-partial*

A StreamSource emits candidates as they arrive; every emit replaces what the
source emitted before in the request.  While one is running, the popup is
updated at most every `PartialInterval` milliseconds, and items emitted
before a timeout are kept.

Limitation of the native popup~
The native popup is replaced as a whole with |complete()|, which drops the
selection.  So while nothing is selected, later results are added to the
popup; once you have selected a candidate, results that arrive later are not
shown, so that the popup does not change under you.  Select nothing or press
<C-e> and type again to see them.  pum.vim does not have this limitation.

LANGUAGE SERVERS                                                *goda-cmp-lsp*

Package `ext/source/lsp` is a source backed by a language server, which it
starts itself as a child process (one per project root) and talks to over
stdio.  It works the same in Vim and Neovim, since it does not use either
editor's LSP client.

The source carries no settings of its own for any server: you write them in
your config.go, like the parameters of any source.  Add the source once per
server, each under its own name: >go

	import (
	    "github.com/Shougo/goda-cmp.vim/cmp"
	    "github.com/Shougo/goda-cmp.vim/ext/filter/sortertext"
	    "github.com/Shougo/goda-cmp.vim/ext/source/lsp"
	)

	b.AddSource(lsp.New(lsp.Params{
	    Name:        "gopls",
	    Command:     []string{"gopls"},
	    Filetypes:   []string{"go", "gomod"},
	    RootMarkers: []string{"go.work", "go.mod", ".git"},
	    // Settings answer workspace/configuration.
	    Settings: map[string]any{"gopls": map[string]any{
	        "usePlaceholders": false,
	    }},
	}))
	b.AddFilter(sortertext.New())
	// Only where the server works: its own filetypes.
	b.PatchFiletypes([]string{"go", "gomod"}, cmp.Config{
	    Sources: []string{"gopls", "around"},
	    SourceOptions: map[string]cmp.SourceOption{
	        "gopls": {
	            Mark:                   "LSP",
	            ForceCompletionPattern: `\.\w*`,
	            Matchers:               []string{},
	            Sorters:                []string{"sortertext"},
	        },
	    },
	})
<
The source options matter:
	forceCompletionPattern	where the server completes without a word
				typed yet, such as after "." (gopls) or "::"
				and "->" (C++).  Without it the popup waits
				for minAutoCompleteLength characters.
	matchers		Most servers filter (fuzzily) themselves; an
				empty list keeps their answer as it is.
	sorters			sortertext keeps the server's order.

	ConfirmBehavior		(a Params field) what an accepted item does to
				the rest of the word after the cursor, when
				the server offers both: "insert" (default)
				keeps it, "replace" replaces it.

What it does:
- The whole buffer is sent when its |b:changedtick| moved (full
  synchronization; goda-cmp tells sources the text, not the changes).
- Items are inserted with |complete()|, so one line each; snippets are not
  requested, and when a server sends them anyway their placeholders are
  turned into plain text.
- Selecting an item resolves it (documentation in the info).
- Accepting an item replaces the text after the cursor that its edit covers
  (see ConfirmBehavior), then applies its additionalTextEdits, such as the
  import of a package that was not imported yet, and keeps the cursor where
  it was.
- Entering a buffer of one of `Filetypes` starts the server for its root and
  opens the document, so the first completion does not wait for the server
  to start; deleting or wiping out the buffer closes the document.  Without
  `Filetypes`, that happens for files of every filetype.
- When the plugin stops, the servers are shut down.

When items start at different columns (gopls' postfix completions start at
the expression, not at the word), all are aligned to the leftmost column: the
text in between becomes part of the other words, and the popup shows them
without it.

Not done: commands attached to items, and edits that start on another line.

FAQ                                                             *goda-cmp-faq*

Q: Nothing is offered.
A: Check `:echo goda#plugins()` (it should list "cmp") and `:echo goda#log()`.

Q: The build says "go.mod requires go >= 1.26" (or similar).
A: Your go command is older and does not download Go 1.26 by itself, usually
   because $GOTOOLCHAIN is "local" (some distributions set that).  Install
   Go 1.26 from https://go.dev/dl/, or set $GOTOOLCHAIN to "auto".

Q: gopls (or go vet) says "new(10) requires go1.26 or later", with a newer
   Go installed.
A: The language version is the "go" line of the module's go.mod, not the
   installed Go.  A configuration made with an older Go still says, for
   instance, "go 1.24".  Run `go mod edit -go=1.26` in the configuration
   directory (`go get` of a goda-cmp.vim that needs Go 1.26 does it too),
   then restart gopls.

Q: The handshake or "protocol" error when starting.
A: The binary was built with a different version of the goda.vim module than
   the goda.vim plugin.  Run `go get -u github.com/Shougo/goda.vim` in the
   configuration directory and |goda_cmp#build()|.
